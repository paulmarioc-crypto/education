# MedStudy

Personalized diagnosis & anatomy learning app: a shared spaced-repetition +
mastery/confusion-tracking engine underneath four study modules (Diagnosis
Game, Anatomy Guesser, Adaptive Quiz Engine, Recall/Review).

Architecture: **hosted, single-user.** The server (Express + Postgres) runs
on a small always-on host, so your phone, tablet, and PC all just open one
URL — nothing needs to be running locally on any of your devices. See
`server/src/index.ts` for how the API and static web app share one process.

Currently implemented (Stage 1 of the build order): the data model, FSRS
spaced-repetition core, PIN auth, and a barebones flashcard review UI. The
other modules (Diagnosis Game, Anatomy Guesser, Quiz Engine, mistake-diagnosis
engine, gamification) land in later stages.

## Hosted deploy (Render + Neon)

This gets the app reachable from your Lenovo tablet, iPhone, and PC without
any of them needing to be on or nearby — free tier on both services is
enough for single-user daily use. Cold starts after ~15 min idle take
20-50 seconds; that's the tradeoff for "free and always reachable."

1. **Database — [neon.tech](https://neon.tech):** sign up, create a project.
   Copy the connection string it gives you (starts with `postgresql://`) —
   you'll need it in step 3.
2. **Push this repo to GitHub** if you haven't (it's already on the
   `claude/medstudy-learning-app-azh5m7` branch).
3. **Web service — [render.com](https://render.com):** sign up, "New +" →
   "Blueprint", connect this repo. Render reads `render.yaml` at the repo
   root and pre-fills a web service. When it asks for env vars, set:
   - `DATABASE_URL` → the Neon connection string from step 1
   - `MEDSTUDY_PIN` → the PIN you'll type to unlock the app
   - `ANTHROPIC_API_KEY` → needed from Stage 2+, can leave blank for now
   - `MEDSTUDY_SESSION_SECRET` is auto-generated by the blueprint
4. Deploy. Render builds and gives you a URL like
   `https://medstudy-xxxx.onrender.com`.
5. Open that URL on your tablet (and phone, and PC) and "Add to Home
   Screen" — it's a PWA, so it installs like a native app. Same URL, same
   data, every device.

No `render.yaml`/Blueprint support on your platform of choice? Any Node
host that gives you a Postgres database works the same way: build command
`npm install && npm run build:server && npm run build:web`, start command
`npm run db:deploy && npm start`, same env vars as above.

## Local development

```bash
npm install                                  # installs both workspaces
cp server/.env.example server/.env           # then edit DATABASE_URL/PIN/secret
npm run db:migrate                           # creates tables in your Postgres
npm run db:seed                              # loads a small starter deck
```

`server/.env` needs a real Postgres `DATABASE_URL` — either a local Postgres
instance or a spare Neon project. Then:

```bash
npm run dev:server   # terminal 1 — API on :4000
npm run dev:web      # terminal 2 — Vite dev server, proxies /api to :4000
```

Or to run it the way it runs in production (one process, built assets):

```bash
npm run build:server
npm run build:web
npm start
```

## Project layout

```
web/          React + TypeScript + Tailwind PWA
render.yaml   Render Blueprint (see "Hosted deploy" above)
```

attempts, confusion pairs, mastery scores, review state).
